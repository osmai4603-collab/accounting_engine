# 📊 قياس جودة المحرك (Engineering Metrics)

هذا الملف مكمل لـ [الدليل الهندسي لبناء المحركات البرمجية](./software_engines.md)، ويعرض مقاييس تساعد على تقييم جودة المحرك ومراجعتها.

لا يمكن الحكم على جودة المحرك من شكل الكود أو عدد الملفات أو استخدام Design Patterns وحدها؛ يجب أن تكون لدينا مقاييس يمكن اختبارها ومراجعتها.

## 1. Functional Correctness

هل ينفذ المحرك القواعد المطلوبة بصورة صحيحة؟

مقاييس مقترحة:

| المقياس                | ماذا يقيس؟                               |
| ---------------------- | ---------------------------------------- |
| Requirement Coverage   | نسبة المتطلبات التي تم تنفيذها واختبارها |
| Business Rule Coverage | نسبة القواعد التي لها اختبارات           |
| Defect Rate            | معدل الأخطاء المكتشفة                    |
| Regression Rate        | نسبة الأخطاء الناتجة عن تغييرات جديدة    |

مثال: إذا كان المحرك يحتوي على 100 قاعدة عمل، فيجب أن نعرف أي القواعد تم اختبارها، وأيها لم يتم اختبارها.

## 2. Performance Metrics

هل المحرك سريع وفعال؟

| المقياس      | ماذا يقيس؟                           |
| ------------ | ------------------------------------ |
| Latency      | زمن تنفيذ العملية                    |
| P50          | الزمن الوسيط                         |
| P95          | الزمن الذي تنتهي عنده 95% من الطلبات |
| P99          | الزمن الذي تنتهي عنده 99% من الطلبات |
| Throughput   | عدد العمليات في الثانية              |
| CPU Usage    | استهلاك المعالج                      |
| Memory Usage | استهلاك الذاكرة                      |

مثال توضيحي لمتطلبات الأداء:

- P95 أقل من 100ms لعملية حسابية محددة.
- معالجة 1,000 عملية في الثانية ضمن بيئة اختبار محددة.
- عدم تجاوز استهلاك الذاكرة ميزانية محددة.

لا تعتمد هذه الأرقام كمعايير عامة؛ يجب اشتقاقها من طبيعة العمليات والأحمال المتوقعة.

## 3. Reliability Metrics

هل يمكن الاعتماد على المحرك؟

| المقياس        | ماذا يقيس؟            |
| -------------- | --------------------- |
| Failure Rate   | نسبة العمليات الفاشلة |
| Error Rate     | نسبة الأخطاء          |
| Recovery Time  | زمن التعافي           |
| Data Integrity | سلامة البيانات        |
| Availability   | نسبة توفر الخدمة      |

من المهم أن تفرق بين Reliability وAvailability؛ فقد تكون الخدمة متاحة تقنياً، لكنها تنتج نتائج خاطئة.

## 4. Maintainability Metrics

هل يمكن صيانة المحرك وتطويره؟

مقاييس مفيدة:

- Cyclomatic Complexity.
- Cognitive Complexity.
- Code Duplication.
- Dependency Coupling.
- Change Failure Rate.
- Mean Time to Repair.

لا تستخدم هذه الأرقام منفردة للحكم على جودة التصميم؛ بل استخدمها لتحديد المناطق التي تحتاج إلى مراجعة.

## 5. Testability Metrics

هل يمكن اختبار المحرك دون تشغيل التطبيق بأكمله؟

من المقاييس:

- Unit Test Coverage.
- Integration Test Coverage.
- Contract Test Coverage.
- Mutation Testing Score.
- Test Execution Time.

تغطية الاختبارات وحدها لا تعني أن الاختبارات جيدة. قد تصل إلى 100% من تغطية الأسطر دون اختبار الحالات الحرجة.

## 6. Security Metrics

هل المحرك آمن؟

- عدد الثغرات المفتوحة حسب مستوى الخطورة.
- عدد الاعتماديات المعروفة بوجود ثغرات فيها.
- نتائج Static Analysis.
- نتائج Dependency Scanning.
- نجاح اختبارات التحكم في الوصول.
- سلامة إدارة الأسرار والصلاحيات.

## 7. Scalability Metrics

هل يستطيع المحرك التعامل مع زيادة حجم العمل؟

- زيادة Throughput عند زيادة الموارد.
- تغير Latency مع زيادة الحمل.
- استهلاك الموارد مع زيادة حجم البيانات.
- قدرة المكونات على العمل بالتوازي.
- تأثير الحمل على قاعدة البيانات.

> 📌 **مرجع:** يساعد ISO 25020 و25023 في بناء منهجية القياس، بينما يحدد ISO 25010 خصائص الجودة التي نريد تقييمها.
