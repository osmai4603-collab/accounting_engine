# ADR-0002 — مسار Go Module وسياسة الإصدار والتوافق

- **الحالة:** معتمد
- **التاريخ:** 2026-11-14
- **المالك:** مالك المشروع
- **يخدم:** `P0-04`, `P1-06`

## السياق

`go.mod` يستخدم `module accounting_engine`، وهو مسار غير قابل للنشر لأن Go Modules تتطلب مسارًا يعبّر عن مستودع حقيقي. لا يمكن لمشروع خارجي استيراده دون `replace`. كما لا توجد سياسة موثقة تغطي Go API وSPI وProtobuf.

## البدائل

1. إبقاء `accounting_engine` واستخدام `replace`: لا يحقق الاستهلاك الخارجي، ويفشل معيار P1-06.
2. اختراع مسار جديد دون مستودع: مرفوض لأنه لا يُنشر.
3. استخدام مسار المستودع الفعلي `github.com/osmai4603-collab/accounting_engine`: قابل للنشر ويتوافق مع remote. (المختار)

## القرار

- **Module path:** `github.com/osmai4603-collab/accounting_engine`.
- **SemVer 2.0.0:**
  - MAJOR: أي كسر في `pkg/api/v1`, `pkg/spi`, أو Protobuf، أو إزالة رمز عام.
  - MINOR: إضافة متوافقة (نوع/دالة/حقل اختياري/Service جديد).
  - PATCH: إصلاح متوافق دون تغيير سلوك محاسبي مقصود.
- **الإهمال:** يبقى الرمز المهمَل إصدار MINOR واحدًا على الأقل، ويُذكر البديل وتاريخ الإزالة المتوقع.
- **Protobuf:** لا يُعاد استخدام أرقام أو أسماء الحقول المحذوفة؛ تُحجز `reserved`.
- **الصدق في الادعاء:** لا يُنشر إصدار مستقر قبل اجتياز Release Gates.

## النتائج

- تحديث كل الاستيرادات آليًا إلى المسار الجديد، ثم `go mod tidy` و`go test ./...`.
- إضافة فحص توافق API في CI (P7-02) وفشل عند كسر غير معلن.
- لا تغيير في `go` أو `toolchain` directives.

## معايير التحقق

- `go list -m` يعرض المسار الرسمي.
- مشروع خارجي نظيف يستورد الوحدة دون `replace` (P3-05/P7-06).
- `go build ./...` و`go test ./...` ينجحان بعد إعادة التسمية.
