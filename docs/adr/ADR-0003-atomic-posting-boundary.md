# ADR-0003 — Atomic Posting Boundary

- **الحالة:** معتمد
- **التاريخ:** 2026-11-12
- **المراجعة:** 2026-11-12
- **المالك:** `ARCH` + `LEDGER` + `DBA`
- **الفجوات المرتبطة:** `GAP-PST-01`, `GAP-PST-04`, `GAP-PST-05`, `GAP-PST-06`, `GAP-PST-07`, `GAP-PST-09`
- **المهام المرتبطة:** `P1-T2`, `P1-T5`, `P1-T6`

## السياق

`internal/posting/engine.go::prepareForPosting` يقرأ حالة الفترة قبل فتح معاملة الترحيل، ثم يفوّض الكتابة إلى `storage/postgres`. لا تعيد طبقة التخزين قراءة حالة الفترة أو قفل صفها داخل المعاملة. كذلك:
- مسار العكس الاحتياطي يحفظ ثم يرحّل ثم يحدّث الأصل على مراحل.
- الترحيل الجماعي يتراجع إلى ترحيل متسلسل عند غياب `BulkRepository`.
- مسار PostgreSQL للعكس لا يثبت أن أسطر العكس تعكس الأصل.

## القرار

1. **حدّ الذرّية هو معاملة الترحيل الواحدة.** كل ما يؤثر في القيد (حالة الفترة، حالة المسودة، البصمة، التسلسل، الأسطر، القيود المساعدة، التدقيق) يُقرأ ويُكتب داخل نفس المعاملة.
2. **ترتيب الأقفال الملزم:**
   1. `fiscal_periods` — `SELECT ... FOR UPDATE` والتحقق من `open` داخل المعاملة.
   2. `journals` — `FOR UPDATE` لاستهلاك التسلسل.
   3. `account_moves` — `FOR UPDATE` للمسودة/الأصل.
   4. القيود المساعدة (`fixed_assets`, `subledger_open_lines`, ...) بترتيب ثابت لمنع الجمود.
3. **عقد التخزين `PostingStoragePort`:**
   - `PostEntryAtomic(ctx, entry, expectedFingerprint) (JournalEntry, error)`
   - `PostReversalAtomic(ctx, originalID, reversal, expectedFingerprint) (JournalEntry, error)`
   - `PostBulkAtomic(ctx, entries) ([]JournalEntry, error)`
   - `PostWithAttachmentsAtomic(ctx, entry, attachments) (JournalEntry, error)`
   كل دالة تُنفّذ التحقق والقفل والكتابة داخل معاملة واحدة، وتُرجع خطأً مصنّفاً (`conflict`/`infrastructure`/`validation`) لا خطأ نصياً.
4. **العكس:** يجب أن تُثبت المعاملة أن كل سطر عكسي يساوي سطر الأصل بالمبلغ والاتجاه المعاكس، وأن `OriginalEntryID` يشير إلى أصل `posted` غير معكوس. أي اختلاف يفشل بـ`ATOMICITY_VIOLATION` أو `ENTRY_INVALID`.
5. **الجماعي:** إما معاملة واحدة تنجح بالكامل أو تفشل بالكامل. لا يوجد تراجع صامت إلى ترحيل متسلسل. غياب `BulkRepository` خطأ إعداد (`infrastructure`)، لا سلوك بديل.
6. **التسلسل:** لا يُستهلك رقم التسلسل إلا إذا نجحت المعاملة. فشل لاحق يعيد الرقم عبر rollback، لا عبر تعويض يدوي.
7. **المرفقات:** تُنفَّذ داخل نفس المعاملة، وأي فشل فيها يبطل القيد بالكامل.

## البدائل المرفوضة

| البديل | سبب الرفض |
| --- | --- |
| التحقق قبل المعاملة ثم الثقة بالحالة | يسمح بإقفال الفترة بين القراءة والكتابة (سباق حقيقي) |
| معاملة لكل قيد داخل الدفعة | ينتج ترحيلاً جزئياً وقابلاً لإعادة المحاولة بشكل مضاعف |
| تعويض يدوي عند فشل العكس | يترك أثراً مالياً وسيطاً وقيداً عكسياً بلا أصل صحيح |
| الاحتفاظ بالمسار التسلسلي كاحتياط | يجعل السلوك يعتمد على نوع التخزين لا على العقد |
| قفل الجدول كله | يقتل التزامن ولا يلزم إلا عند الحاجة |

## النتائج

- يصبح فشل الترحيل ذرّياً وقابلاً للتصنيف.
- تحتاج اختبارات PostgreSQL إلى محاكاة فشل بعد القفل وقبل commit.
- يجب توحيد سلوك Memory وMock مع PostgreSQL أو رفض العملية صراحةً.
- تزداد أهمية اختبارات الجمود وترتيب الأقفال.

## المخاطر

| المخاطرة | التخفيف |
| --- | --- |
| معاملات أطول | قصر النطاق، فهارس، وقياس `transaction_duration` |
| جمود بين المسارات | ترتيب أقفال ثابت واختبارات تزامن |
| كسر واجهات تخزين قائمة | إصدار رئيسي + محولات توافق + ADR-0005 |
| فشل اختبارات قديمة تفترض الترحيل التسلسلي | تحديث الاختبارات لعقد «الكل أو لا شيء» |
