# ADR-0001 — نقطة الدخول العامة الواحدة وPublic SPI

- **الحالة:** معتمد
- **التاريخ:** 2026-11-14
- **المالك:** مالك المشروع
- **يخدم:** `P0-04`, `P1-01`, `P1-02`, `P1-05`

## السياق

يوجد اليوم مسارَان عامّان: Root package `accounting_engine` و`pkg/sdk`. كلاهما يستورد `internal/*`، وRoot يصدّر أنواعًا داخلية في توقيعاته (`ifrs9.Unit`, `posting.BulkRepository`, `observability.Metrics`). نتيجة ذلك أن أي مستهلك خارجي لا يستطيع استيراد API المحرك أصلًا، لأن Go تمنع الوصول إلى `internal` عبر الحزم العامة.

## البدائل

1. **إبقاء Root كواجهة أساسية**: يتطلب إعادة كتابة كل توقيعاته وإزالة كل الأنواع الداخلية، ويترك مسارَي دخول متنافسين.
2. **حذف Root فورًا**: أنظف، لكنه يكسر مستهلكي `cmd/agy` والاختبارات دون فترة توافق.
3. **Root كواجهة توافق مهمَلة (Deprecated Facade) تستدعي `pkg/sdk`**: يحقق النقاء ويحفظ التوافق المؤقت. (المختار)

## القرار

1. `pkg/sdk` هو نقطة الدخول العامة الوحيدة الموصى بها.
2. يُحوَّل Root package إلى Facade مهمَل:
   - كل رمز عام يحمل تعليق `Deprecated: use ...`.
   - لا يصدّر أي نوع من `internal/*` ولا أي نوع PostgreSQL/SQL.
   - يعيد تصدير أنواع عامة فقط (Aliases) ويستدعي `pkg/sdk`، دون تكرار منطق أو تهيئة.
3. اتجاه الاعتماد: `accounting_engine (root) → pkg/sdk → pkg/api|pkg/spi`. يُمنع أن يستورد `pkg/sdk` أو `internal/*` الحزمة الجذرية.
4. الخطة: نقل تنفيذ المحرك القديم إلى `internal/legacyengine` لخدمة `cmd/agy` والاختبارات، لا للمستهلكين.
5. الإزالة النهائية للـ Facade في أول إصدار MAJOR بعد استقرار SDK، مع إشعار إهمال لا يقل عن إصدار MINOR واحد.

## النتائج

- تُوسّع `check_public_api_purity.sh` لتفحص Root و`pkg/**` وتمنع `internal` في أي حزمة عامة.
- تُضاف اختبارات استهلاك خارجي لكل من SDK والFacade.
- أي رمز جذري لا يمكن التعبير عنه بأنواع عامة يُهمل أو يُزال من الـ Facade.

## معايير التحقق

- `go doc -all .` لا يعرض أي مسار `internal/` في التوقيعات.
- مشروع Go خارجي يستورد `pkg/sdk` ويبني دون `replace` داخلي ودون `internal` imports.
- `pkg/sdk` لا يستورد Root package.
