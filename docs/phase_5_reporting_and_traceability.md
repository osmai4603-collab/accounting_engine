# المرحلة الخامسة: وحدات التقارير والمطابقة والتتبع المالي

## Phase 5: Reporting, Reconciliation & Financial Traceability Units

**الهدف العام للمرحلة:** تزويد المحرك المحاسبي بقدرات التتبع المالي الكامل (End-to-End Financial Traceability) للمدققين، وتأمين سلامة الأرصدة المادية المخزنة ومطابقتها الدورية، وتوسيع محرك التقارير ليشمل القوائم المالية المقارنة والإفصاحات الإلزامية وفق معايير المحاسبة الدولية.

---

### المهمة 5.1: وحدة التتبع المالي والتدقيق المالي المعكوس (Financial Traceability Unit)

* **المشكلة الحالية:**
  عندما يظهر رقم أو رصيد في قائمة مالية (مثل رصيد النقدية أو الذمم المدينة)، لا توجد وسيلة برمجية آلية موحدة تمكن المدقق أو المستخدم من الانتقال التنازلي التفاعلي (Drill-Down) من بند القائمة إلى الحساب، ثم إلى قيود اليومية، ثم إلى الحدث الاقتصادي، وصولاً إلى المستند الأصلي الخارجي (Invoice / Payment Advice).
* **الهدف:**
  بناء وحدة `FinancialTraceabilityUnit` توفر مسار تتبع مالي ثنائي الاتجاه يربط أي رقم في القوائم المالية بالوثيقة الاقتصادية الأصلية والعكس.
* **السياق الفني والمحاسبي المطلوب:**
  * **معايير التدقيق الدولية (ISA):** معيار التدقيق الدولي **ISA 500 (أدلة التدقيق)** الذي يشترط كفاية وملاءمة أدلة التدقيق وإمكانية التحقق من أصل المعاملات (Audit Trail / Lineage).
  * **قانون ساربينز أوكسلي (SOX Section 404):** متطلبات إثبات صحة الرقابة الداخلية على إعداد التقارير المالية والقدرة على إعادة تتبع أي رقم محاسبي لمصدره المعتمد.
* **خطوات التنفيذ المحددة:**
  1. بناء خدمة التتبع العكسي:

     ```text
     [Financial Statement Line]
              ↓
     [Account Trial Balance]
              ↓
     [Posted Journal Move Lines]
              ↓
     [Journal Entry Move Header]
              ↓
     [Economic Event]
              ↓
     [External Source Reference & Document Payload]
     ```

  2. توفير واجهة برمجية:

     ```go
     type TraceResult struct {
         StatementItem   string
         AccountID       uuid.UUID
         MoveLines       []AccountMoveLine
         JournalEntries  []JournalEntry
         SourceEvents    []EconomicEvent
         AuditChainProof string // إثبات التشفير من سلسلة الهاش WORM
     }
     func (u *FinancialTraceabilityUnit) TraceStatementItem(ctx context.Context, reportID string, lineItem string) (TraceResult, error)
     ```

* **معايير قبول نفاذ المهمة (Acceptance Criteria):**
  * [ ] اختيار أي رقم في قائمة المركز المالي واستخراج كامل قائمة القيود والأحداث الاقتصادية المكونة له بطلب برمجي واحد.
  * [ ] التحقق من تطابق مجموع سطور القيود المسترجعة مع الرقم الظاهر في القائمة بنسبة تطابق 100% دون أي فارق عشري.

### المهمة 5.2: وحدة فحص ومطابقة وإعادة بناء الأرصدة المادية (Materialized Balances Integrity Unit)

* **المشكلة الحالية:**
  يعتمد المحرك على جدول الأرصدة المادية `account_balances` لتسريع الاستعلامات والتقارير. ورغم وجود نقاط تفتيش، فإن أي عطل غير متوقع أو عملية تحديث غير مكتملة قد تسبب انحرافاً صامتاً (Drift) بين الرصيد المخزن في جدول الأرصدة ومجموع الحركات الفعلية في جدول القيود `account_move_lines`.
* **الهدف:**
  بناء وحدة `BalanceIntegrityUnit` لتنفيذ مطابقة مستقلة ودورية مستمرة، مع توفير خاصية إعادة البناء التام للأرصدة (Zero-Downtime Balance Rebuild) من الحركات المحاسبية غير القابلة للتعديل.
* **السياق الفني والمحاسبي المطلوب:**
  * **مبادئ سلامة قواعد البيانات المالية (ACID & Eventual Consistency Validation):** الحركات في دفتر الأستاذ العام هي المصدر المطلق للحقيقة (Single Source of Truth)، بينما الأرصدة التراكمية هي مجرد عروض مادية مسرعة (Read Optimizations) يجب أن تظل متطابقة مع المصدر.
* **خطوات التنفيذ المحددة:**
  1. إنشاء مهمة فحص دورية (Scheduled Audit Task) تفحص المعادلة:
     $$\text{Stored Balance} \stackrel{?}{=} \sum \text{Debit Lines} - \sum \text{Credit Lines}$$
  2. عند اكتشاف أي انحراف، تسجيل تنبيه حرج (Critical Alert) في سجل التدقيق وإظهار تفاصيل الحساب المتأثر.
  3. بناء آلية آمنة لإعادة احتساب وتصحيح الأرصدة المادية بناءً على الحركات الفعلية مع الحفاظ على الأقفال الذرية.
* **معايير قبول نفاذ المهمة (Acceptance Criteria):**
  * [ ] اختبار محاكاة لخطأ يدوي في جدول `account_balances` وإثبات قدرة الوحدة على اكتشافه خلال فحص الاتزان.
  * [ ] تشغيل دالة `RebuildBalancesFromLines` وإثبات استعادة الأرصدة الصحيحة بالكامل ومطابقتها لميزان المراجعة.

### المهمة 5.3: تطوير القوائم المالية المقارنة والإفصاحات (Comparative Statements & Disclosures Unit)

* **المشكلة الحالية:**
  تولد محركات التقارير الحالية القوائم المالية للفترة المحددة فقط، وتفتقر إلى استخراج القوائم المقارنة مع الفترات السابقة (Comparative Periods: السنة الحالية مقابل السنة السابقة، أو الربع الحالي مقابل نفس الربع من العام الماضي)، كما تفتقر إلى ربط أرقام القوائم بهياكل الإفصاحات والإيضاحات المتممة (Notes to the Financial Statements).
* **الهدف:**
  ترقية `FinancialReportingUnit` لتوليد حزم القوائم المالية المقارنة الكاملة، ودعم إعادة التبويب وفق معايير العرض الدولية.
* **السياق الفني والمحاسبي المطلوب:**
  * **معيار المحاسبة الدولي IAS 1 (عرض القوائم المالية):**
    * الفقرة 38: وجوب تقديم معلومات مقارنة بالنسبة للفترة السابقة لجميع المبالغ الواردة في القوائم المالية للسنة الحالية.
    * متطلبات حزمة القوائم الكاملة: المركز المالي، الدخل الشامل، التغيرات في حقوق الملكية، التدفقات النقدية، والإيضاحات المتممة.
  * **معيار التقرير المالي الدولي IFRS 8 (القطاعات التشغيلية):** الإفصاح عن نتائج الأنشطة بحسب القطاعات التحليلية الجغرافية والتشغيلية.
* **خطوات التنفيذ المحددة:**
  1. تحديث دوال توليد الميزانية العمومية وقائمة الدخل لتقبل فترات مقارنة:

     ```go
     type ComparativeBalanceSheet struct {
         CurrentPeriodDate  time.Time
         PriorPeriodDate    time.Time
         Lines              []ComparativeStatementLine
         Currency           string
     }
     type ComparativeStatementLine struct {
         LineCode      string
         Description   string
         CurrentAmount decimal.Decimal
         PriorAmount   decimal.Decimal
         Variance      decimal.Decimal
         VariancePct   decimal.Decimal
     }
     ```

  2. ربط القوائم بنظام التصنيف والإفصاحات (Taxonomy & Notes Attachment) لإنتاج حزمة تقارير جاهزة للنشر والتدقيق الخارجي.
* **معايير قبول نفاذ المهمة (Acceptance Criteria):**
  * [ ] استخراج ميزانية عمومية مقارنة لسنتي 2025 و 2024 وتأكيد صحة احتساب مبالغ التغير (Variance) ونسبتها المئوية.
  * [ ] توليد قائمة التدفقات النقدية المقارنة بالطريقة غير المباشرة والتأكد من مطابقة النقدية في نهاية الفترة مع النقدية في الميزانية العمومية.
