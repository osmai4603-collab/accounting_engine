# ARD-P12-02 — Rate Limiting for Standalone Service

- **الحالة:** مكتمل
- **التاريخ:** 2026-11-17
- **النطاق:** حماية HTTP وgRPC في `cmd/accounting-service` فقط.
- **القرار:** استخدام Token Bucket داخل الذاكرة، مع حارس IP قبل المصادقة وحصة tenant بعد المصادقة.

## التنفيذ

1. `internal/ratelimit` يوفر محددًا آمنًا للتزامن بحدود ذاكرة (`MaxKeys`) وتنظيف للدلاء الخاملة.
2. توجد سعتان لكل فئة:
   - قراءة: 60 طلبًا لكل نافذة لكل tenant، و600 طلب لكل نافذة لكل IP.
   - كتابة/ترحيل: 20 طلبًا لكل نافذة لكل tenant، و200 طلب لكل نافذة لكل IP.
3. حارس IP يُطبق أولًا، بما في ذلك طلبات المصادقة الفاشلة. بعد نجاح المصادقة يُطبق حد مستقل على `TenantID` الموثوق؛ عند غيابه يستخدم المحدد عنوان IP للنظير. لا تُقبل رؤوس Forwarded غير الموثوقة.
4. HTTP يقيّد `/api/v1/*` فقط ويرد بـ `429` و`Retry-After` وجسم الخطأ المعتاد. فحوصات الصحة والمقاييس مستثناة.
5. gRPC يقيّد Unary وStreaming. تسبق حصة IP المصادقة، وتعمل حصة tenant بعدها؛ التجاوز يعيد `RESOURCE_EXHAUSTED` وtrailer `retry-after`.
6. متغيرات الإعداد: `RATE_LIMIT_ENABLED`، `RATE_LIMIT_READ_REQUESTS`، `RATE_LIMIT_WRITE_REQUESTS`، `RATE_LIMIT_CLIENT_READ_REQUESTS`، `RATE_LIMIT_CLIENT_WRITE_REQUESTS`، `RATE_LIMIT_WINDOW`، و`RATE_LIMIT_MAX_KEYS`.
7. لم تُضف أي تبعيات، ولم تتغير `go.mod` أو `pkg/sdk/` أو `pkg/spi/`.

## التحقق

- `go test -race ./internal/ratelimit ./cmd/accounting-service/...` — ناجح.
- تغطي الاختبارات فصل القراءة والكتابة، إعادة تعبئة الرموز، حد الذاكرة والتنظيف، التزامن، إعدادات البيئة، عزل tenant، حماية IP قبل المصادقة، HTTP `429` وgRPC `RESOURCE_EXHAUSTED` لـ Unary وStreaming.
- `go test ./...` — اجتازت حزم المهمة وباقي الحزم، لكن فشل اختبار DR خارج النطاق `test/dr/dr_drill_test.go` في فحص RLS (`cross-tenant UPDATE touched 1 rows`).

## حدود التشغيل

الدلاء داخل الذاكرة ومستقلة لكل عملية؛ لا توجد حصة موزعة أو مشاركة بين نسخ الخدمة. عند النشر متعدد النسخ، تُضاف الحصة الموزعة عند Gateway أو عبر مخزن مشترك خارج النواة. حدود SDK المدمج لا تتغير.
