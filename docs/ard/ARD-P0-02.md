## 1. كيف تم التنفيذ

- الالتزام بحدود التوازي: لم يُعدّل أي كود أو حزمة؛ أُعيد توليد الخريطة فقط.
- أوامر القياس:
  - `go list -f '{{.ImportPath}}|{{join .Imports " "}}' ./...` → 44 package.
  - `go doc -all .` و`go doc -all ./pkg/sdk` لجرد التصدير.
  - `grep` على migrations: 48 ملف migration، 17 ملفًا يعرّف Triggers/RLS.
  - استعلامات PostgreSQL: 122 جدولًا، 107 سياسة RLS، 36 trigger غير داخلي في `accounting_test`.
- إعادة كتابة `docs/architecture/current_dependency_map.md` لتشمل:
  - مجموعات الحزم الفعلية.
  - جدول اتجاه الاعتماديات بين الحدود.
  - تحليل Root package وأنواعه الداخلية.
  - جدول تسريبات `internal` في الحزم العامة، مع التوضيح أن `pkg/sdk` يستورد `internal` فعليًا رغم نجاح فحص النقاء الحالي.
  - عمليات الكتابة والقيود وTriggers.
  - الملفات المشتركة عالية الحساسية.
  - سبعة مسارات إصلاح مرتبطة بالمهام.
