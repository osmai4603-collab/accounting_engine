# ARD-P12-01 — Live Disaster Recovery Drill & NO-GO Condition Clearance

- **Status:** Complete / Approved
- **Date:** 2026-11-17
- **Scope:** Physical backup (`pg_dump -Fc`), clean restoration (`pg_restore`), full accounting integrity validation suite, and engine operational resumption on PostgreSQL.
- **Decision:** Remove the standalone production NO-GO blocker for PostgreSQL disaster recovery based on automated, end-to-end live recovery verification (`test/dr/dr_drill_test.go`) and update operational runbooks.

---

## 1. Context & Motivation

The v0.1.0 release notes (`RELEASE_NOTES.md`) placed a formal **NO-GO** condition on unattended standalone production deployment until a live physical database backup and restore drill (`pg_dump` / `pg_restore`) was executed and documented, proving that:

1. Backups taken from an active engine database with multi-company, closing, reversing, and audit data restore cleanly without schema re-migration.
2. All 6 fundamental accounting integrity invariants pass 100% on the restored database.
3. The engine can resume normal operations (drafting, posting, idempotency, reporting, closing) on the restored target.

---

## 2. Test Execution & Evidence

The drill harness is implemented in `test/dr/` (`dr_drill_test.go`, `harness_test.go`, `snapshot_test.go`).

### Test Procedure

1. **Source Population:** Provisioned realistic production-like ledger data across multiple companies (`Company A` and `Company B`), including:
   - Initial balances and multi-currency transactions.
   - Adjusting and reversing journal entries.
   - Closed fiscal years and retained earnings opening entries (`P9-01`).
   - Tamper-evident cryptographic audit logs (`financial_audit_logs`).
2. **Pre-backup Fingerprint:** Captured exact quantitative state (`drillSnapshot`): move counts, line counts, balance rows, audit log counts, sequence counters, and functional currency totals.
3. **Backup (`pg_dump`):** Dumped source DB to binary custom format (`-Fc`):
   - Duration: 154 ms
   - Dump file size: ~251 KB
4. **Restore (`pg_restore`):** Restored to an isolated, freshly created target database:
   - Duration: 1.20 s
5. **Post-Restore Integrity Checks (All Passed 100%):**
   - `03_schema_health`: 32 migrations confirmed in `schema_migrations`, checksums matched, no re-migration required.
   - `04_double_entry_balance`: Every move balances ($\sum \text{Debit} = \sum \text{Credit}$) per entry and per company.
   - `05_balances_match_moves`: Reconciled 12 company/period balance combinations against raw posted lines.
   - `06_audit_hash_chain`: Verified unbroken SHA-256 hash chains across 96 audit logs for both companies.
   - `07_rls_tenant_isolation`: Probed under non-superuser role; zero cross-tenant reads or writes permitted.
   - `08_idempotency_keys`: Reversal keys and unit-of-work idempotency records preserved intact.
   - `09_sequences`: Sequences continued monotonically without numbering collisions.
   - `10_snapshot_parity_rpo`: Restored database fingerprint matched pre-backup fingerprint identically (**RPO = 0**).
   - `11_engine_resumption`: Successfully executed new draft creation, posting, sequence advance, idempotent reversal, trial balance generation, and annual close.
