# ARD-P11-05: Standards Automated Posting Workflow and Contract Parity

## Status

Implemented and verified with 100% Contract Parity across Memory, PostgreSQL, and External adapters.

## Scope and Architectural Decisions

1. **Unified `StandardPostingCapability` Contract (`pkg/spi/standards/posting.go`):**
   - Established a public, transport-neutral capability for standard modules to submit and post balanced entries through the official application layer without direct SQL or bypass of accounting invariants.
   - Added `Posting() StandardPostingCapability` to `ModulePorts` and `NewStandardPoster(app, masterData)`.
   - Adheres strictly to Gate G6 (`Public API Purity`): `pkg/spi/standards/` imports only public APIs and SPI interfaces (`pkg/api/v1/ledger`, `pkg/api/v1/types`, `pkg/spi/application`, `pkg/spi/masterdata`), with zero internal imports.

2. **Mandatory Audit Trail Metadata:**
   - Every posting request requires:
     - `StandardRef`: e.g. `"IFRS-15-REV-REC"`, `"IFRS-9-ECL"`, `"IFRS-9-SUBSEQUENT-MEASUREMENT"`, `"IFRS-16-LEASE"`, `"IAS-12-DEFERRED-TAX"`, `"IAS-12-CURRENT-TAX"`.
     - `EntityID`: Original host entity reference (contract ID, lease reference, financial instrument ID, tax treatment ID).
     - `IdempotencyKey`: Non-empty idempotency key enforcing deduplication for identical operations.
     - `CompanyID`, `JournalID`, `EffectiveDate`, and balanced `Lines`.

3. **Real Chart of Accounts Enforcement:**
   - The capability verifies each entry line's `AccountID` against the real Chart of Accounts via `MasterDataReader.GetAccount(ctx, companyID, accountID)`.
   - Unknown or synthetic account IDs are rejected with `ErrAccountNotFound`, eliminating virtual or unmapped accounts.

4. **Strict Idempotency:**
   - Deterministic entry IDs are derived from `uuid.NewSHA1(NameSpaceOID, CompanyID:StandardRef:IdempotencyKey)` (or passed explicitly by the module).
   - Replaying an identical request retrieves the existing posted entry and returns `IdempotentReplay: true` without duplicating journal entries in the general ledger.

5. **Atomic Binding and Failure Rollback:**
   - State progression in standard modules (e.g., recognized revenue in IFRS 15, carrying amount updates in IFRS 9, lease payment status in IFRS 16, deferred tax positions in IAS 12) is committed **only** after receiving successful posting confirmation from the application layer.
   - If draft creation or posting fails (e.g., due to unmapped account, closed period, or infrastructure failure), the module rolls back and leaves its state uncommitted.

6. **Standard Module Integration:**
   - **IFRS 15 (`modules/ifrs15`):** `RevenuePostingAdapter` adapts `StandardPostingCapability` to `RevenuePostingApplication`. `NewRevenueWorkflow` integrates ports and durable `ContractStore`.
   - **IFRS 9 (`modules/ifrs9`):** Exposes `PostSubsequentMeasurement` and `PostVersionedECL` for host-classified instruments and versioned ECL allowance movements.
   - **IFRS 16 (`modules/ifrs16`):** Moved `IFRS16-POSTING-WORKFLOW` to supported requirements. Exposes `PostCommencement`, `PostPayment`, `PostDepreciation`, `PostLessorOperatingIncome`, `PostLessorFinanceCommencement`, `PostLessorFinanceReceipt`, and `PostExemptionExpense`.
   - **IAS 12 (`modules/ias12`):** Moved `IAS12-POSTING-WORKFLOW` to supported requirements. Exposes `PostDeferredTax` and `PostCurrentTax`.
