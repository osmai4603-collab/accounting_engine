# ARD-P10-01: Public AR/AP Subledger Capability

## Status

Implemented as an optional public SDK capability. AR/AP contracts in
`pkg/api/v1/subledger` and `pkg/spi/subledger` are the integration boundary;
SDK consumers enable it with `sdk.WithSubledgerARAP`. Consumers that do not
configure the option retain the existing engine behavior.

## Decision

Expose company-scoped AR/AP inquiry and accounting-event use cases through a
public API/SPI boundary. Keep persistence adapter-defined and route every
accounting event through `pkg/spi/application.Service`; do not import internal
packages from public packages.

The public service distinguishes inquiry from accounting events:

| Operation | Accounting effect |
| --- | --- |
| Get/list receivables or payables; aging; reconciliation | Read-only; no draft or posting call |
| Create AR/AP invoice | Post a balanced entry: AR control debit / counter-account credit; AP counter-account debit / AP control credit |
| Record collection/payment | Post a balanced entry through AR/AP control and cash accounts, then update allocated open balances |
| Write off | Post a balanced entry through the AR/AP control and adjustment accounts, then reduce the open balance |

Invoice amounts can include a functional-currency amount; absent that amount,
the transaction currency amount is treated as functional currency. Settlement
and write-off allocations preserve the recorded functional residual amount.
Payment allocations across multiple transaction currencies are rejected; the
FX remeasurement and realized-FX workflow belongs to P10-04.

## Contracts and wiring

- Public DTOs and commands are in `pkg/api/v1/subledger/models.go`.
- Public store and service contracts are in `pkg/spi/subledger/stores.go`.
- `sdk.WithSubledgerARAP(ARAPStores{Receivables, Payables, Balance})` validates
  its dependencies before service activation. `sdk.SubledgerARAP(engine)`
  returns `types.ErrCapabilityNotImplemented` if the optional service is off.
- Internal implementation is in `internal/subledgers/public_arap.go`.

The service receives the application-layer service built by the SDK. It creates
a draft, then posts it through the public application use cases; it does not
call the GL posting engine directly.

## Reconciliation evidence

Reconciliation groups open AR/AP residuals by control account and compares
functional balances with the public `storage.BalanceReader`. That reader's
balance is debit-minus-credit; AP's natural credit balance is normalized to a
positive residual before comparison. Evidence includes company, ledger kind,
control account, currency, cutoff, both balances, difference, and a clean/
variance flag. Reconciliation never posts or reserves a journal sequence.

## Known limitations

1. The public application service and the independently supplied AR/AP stores
   do not share an atomic unit of work. Posting is completed before the store
   mutation, so a store failure returns
   `subledger.ErrPostedARAPPersistenceFailed` with the GL
   entry already posted. A durable adapter-level transaction spanning both
   ports is needed to eliminate this failure window.
2. The public AR/AP store contracts do not expose dated mutation history.
   Reconciliation therefore supports current-date evidence only and rejects
   earlier cutoffs rather than presenting a misleading historical balance.
3. Invoice/payment/write-off posting requires the caller to identify journal,
   control, counterparty/cash/adjustment accounts and amounts. Account role
   validation and authorization remain enforced by the application layer and
   the configured master-data/posting policies.
4. Settlement FX differences and foreign-operation translation are outside
   this AR/AP capability; use the bounded P10-04 FX functionality.

## Verification

`internal/subledgers/p10_01_public_arap_test.go` exercises AR and AP invoice
posting, collection, write-off, balance updates, account-side correctness, and
proves read/aging/reconciliation inquiries do not post entries.
`pkg/sdk/p10_01_public_arap_test.go` verifies public consumer imports, builder
dependency validation (including typed-nil dependencies), and optional-service
behavior. Focused package tests are run with:

```sh
go test ./internal/subledgers ./pkg/sdk ./pkg/spi/subledger ./pkg/api/v1/subledger
```

No public adapter currently exposes AR/AP stores as part of `storage.Ports`;
the host must supply its AR/AP stores explicitly to the builder.
