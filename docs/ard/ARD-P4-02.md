# ARD-P4-02: Fiscal Period, Journal and Sequence Lifecycle

- **المهمة:** `P4-02`
- **المرحلة:** `P4`
- **تاريخ الإتمام:** 2026-11-14
- **الحالة عند الإغلاق:** منفذة
- **النطاق:** `internal/masterdata`، `internal/posting`، `internal/adapters/postgres`، SQL migrations، والاختبارات المرتبطة

## 1. القرارات والتنفيذ

1. **دورة الفترة المالية**
   - الانتقالات العادية هي `open -> soft_closed -> hard_closed` فقط؛ القفز بين الحالات، الرجوع إلى حالة أسبق، وإعادة الفتح عبر مسار الإغلاق العادي مرفوضة.
   - إعادة الفتح عملية منفصلة تتطلب UUID للفاعل وسبباً غير فارغ. الانتقال وتحديث الفترة وسجل التدقيق يتمان في معاملة واحدة.
   - تحفظ الفترة آخر فاعل وسبب وتوقيت انتقال؛ كما يحفظ سجل التدقيق كل انتقال، بما في ذلك إعادة الفتح، مع الفاعل والسبب.
   - تقفل عملية الترحيل صف الفترة بـ `FOR UPDATE` داخل معاملة الترحيل. إقفال الفترة يستخدم قفل الصف نفسه؛ لذلك يرى الترحيل الحالة النهائية بعد انتظار الإقفال، وتُلغى معاملة الترحيل وتسلسلها عند كون الفترة مغلقة.

2. **التاريخ الفعلي وتاريخ الترحيل**
   - `EntryDate` (أو الحقل القديم `Date`) هو التاريخ الفعلي المستخدم لاختيار الفترة وتطبيق سياسة أسعار/عملات الإدخال.
   - `PostingDate` تاريخ UTC تقويمي يولّده الخادم عند الترحيل الناجح. تقيس سياسة التأخير الفرق بين التاريخ الفعلي وتاريخ الترحيل، ولا يُستبدل التاريخ الفعلي بتاريخ الترحيل.

3. **دفاتر اليومية**
   - نطاق الدفتر شركة واحدة، ومفاتيح الدفتر وأرقام القيود مقيدة ضمن الشركة؛ رقم اليومية فريد ومتسلسل ضمن الدفتر.
   - السياسة المدعومة حالياً هي `per_journal`. قائمة عملات فارغة تعني السماح بجميع العملات؛ القائمة غير الفارغة تُطبق على عملة المعاملة لكل سطر.
   - لا يرحّل قيد إلى دفتر غير نشط. يمكن تغيير الإتاحة، لكن لا يمكن تغيير سياسة العملة/الترقيم بعد وجود قيود أو مسودات في الدفتر.
   - مفاتيح الشركة/الدفتر الأجنبية تمنع حذف دفتر مستخدم. المشغل الموجود يمنع تغيير رقم قيد مرحّل أو معكوس، والفهرس الفريد يمنع الأرقام المكررة.

4. **حجز التسلسل**
   - حجز أرقام اليومية وتحديث القيد والسطور والتدقيق والمرفقات داخل معاملة PostgreSQL نفسها؛ `ROLLBACK` يعيد العداد إلى قيمته السابقة ولا يستهلك رقماً.
   - المسارات الذرية للقيد المفرد، القيد مع مرفق، العكس، والترحيل الجماعي تستخدم قفل صف الدفتر. الترحيل الجماعي يقفل الدفاتر بترتيب ثابت.

## 3. الحدود والتوافق

- يظل `UpdatePeriodState` الداخلي القديم متاحاً للتوافق مع المستدعين السابقين. المسارات الجديدة التي تتطلب إثبات الفاعل والسبب تستخدم `TransitionPeriodStateContext` و`ReopenPeriodContext`.
- لا يتضمن التغيير واجهة UI أو تغييراً للعقود العامة في `pkg/spi` أو الوحدات.
- تم اختبار التراجع عن التسلسل ضمن مسارات الترحيل الذرية، ولم تُضف سياسة منفصلة لأرقام محجوزة يدوياً خارج الترحيل.
