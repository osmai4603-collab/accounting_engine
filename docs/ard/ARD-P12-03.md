# ARD-P12-03 — Performance Benchmarks and Baseline

- **الحالة:** مكتمل
- **التاريخ:** 2026-11-17
- **النطاق:** قياسات Go للعمليات المحاسبية الحرجة على محول الذاكرة وPostgreSQL.
- **القرار:** حزمة `test/benchmark` تقيس العمليات الست المطلوبة، وتُنشئ schema معزولاً لكل تشغيل PostgreSQL، وتوثّق خط الأساس الفعلي دون فرض عتبات زمنية مطلقة مرتبطة ببيئة واحدة.

## التنفيذ

1. إضافة القياسات `BenchmarkDraftCreation` (2/10/50 سطراً)، `BenchmarkPostingPipeline`، `BenchmarkConcurrentPosting`، `BenchmarkBalanceSheetGeneration` (1,000 حساب)، `BenchmarkCashFlowGeneration` (مباشر وغير مباشر)، و`BenchmarkYearEndClosing`.
2. تشغيل كل قياس على `internal/adapters/memory` وPostgreSQL. يستخدم الترحيل المتزامن قفل PostgreSQL advisory الذي يوفّره المحول.
3. تنفيذ الإقفال السنوي عبر قدرة SDK العامة الذرية، والتحقق من إنشاء قيد الافتتاح؛ إعداد بيانات القياس خارج زمن العملية المقاسة.
4. جعل إعداد PostgreSQL آمناً: schema عشوائي ومعزول، تطبيق migrations داخله، ثم حذفه بعد القياس.
5. توثيق بيئة التشغيل، أوامر إعادة القياس، نتائج `ns/op` و`ops/s` و`B/op` و`allocs/op` في [خط الأساس v0.2.0](../performance/baseline_v0.2.0.md).

## التحقق

- `go test ./test/benchmark -run '^$' -bench . -benchtime=1s -count=1` — نجح؛ جميع القياسات الستة على المحولين.
- `go test -race ./test/benchmark -run '^$' -bench '^BenchmarkConcurrentPosting$' -benchtime=100ms -count=1` — نجح بلا أخطاء سباق.
- لم تُضف تبعيات، ولم يتغير `go.mod`.

## حدود التفسير

النتائج خط أساس رصدي لهذا المضيف وليست SLO أو عتبة CI ثابتة. تتأثر النتائج بالعتاد وحالة PostgreSQL والذاكرة المؤقتة؛ ينبغي مقارنة تشغيلات متكررة على بيئة متماثلة قبل اعتماد تراجع أداء.
